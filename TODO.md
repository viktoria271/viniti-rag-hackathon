## Шаг 2. Модульная архитектура (`core/` + `plugins/rag/`)
Создай модульную структуру (универсальное ядро + плагин RAG, без тяжёлых зависимостей):
- `core/pdf_processor.py` — проверка наличия текстового слоя через `pymupdf`. Для обычных PDF — постраничное извлечение текста с маркерами `--- PAGE N ---` (нумерация с 1). Для синтетических сканов без текста (`is_scan=True`, как `D002`, `D013`, `D021`) — подготовка к мультимодальной отправке PDF напрямую в Gemini (с удалением загруженного файла из облака API после ответа).
- `core/llm_client.py` — обёртка над `google-genai` (Structured Outputs JSON по Pydantic-схеме, retry с паузами при ошибках 429/500, сохранение сырого ответа в `cache/<doc_id>.json`, пропуск уже закэшированных файлов без `--force`).
- `plugins/rag/schemas.py` — Pydantic-модели для одной публикации, строго соответствующие всем 7 CSV из `submission_template/`.
- `plugins/rag/prompts.py` — системный и пользовательский промпты для RAG:
  - классификация статьи (`in_scope` / исключена, но попадает в `publications.csv`);
  - запрет на додумывание пустых полей;
  - разделение `primary` (собственные эксперименты) и `cited` (чужие результаты в сравнительных таблицах);
  - поддержка чисел без нуля (`.204` -> `0.204`), диапазонов (`256-512` в заметки, числовое поле пустое);
  - точная привязка `source_page` (с 1), `source_section`, `source_table` / `source_figure` и дословной цитаты `source_fragment`.
- `plugins/rag/exporter.py` — сборка всех 7 CSV из `cache/` на встроенном модуле `csv` + детерминированный валидатор правил (проверка шкал `[0, 1]` vs `[0, 100%]`, наличие `k` у метрик `@k`, различение `%` и `percentage_points` в дельтах, запись замечаний без удаления исходных строк).
- `main.py` — кроссплатформенная CLI-точка входа (`--input`, `--output`, `--only`, `--force`, `--rebuild-csv-only`).
